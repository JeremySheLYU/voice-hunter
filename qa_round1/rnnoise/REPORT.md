# RNNoise 人聲與背景評估

以三位 LibriSpeech 朗讀者與五種干擾物建立 60 個可重現的五秒混音。每個條件比較未處理的混音和 Voice Hunter 完整雙聲道分軌路徑。**57/60 個條件的人聲 SI-SDR 改善至少 1 dB，中位改善 6.70 dB**，達到預先定義的整體門檻（45/60 個、且中位至少 3 dB）。所有低於 1 dB 的條件都包含同一首配樂。另計 4 個乾淨人聲、5 個無人聲和 1 個靜音控制，總共 66/70 通過各自門檻、4 個未達標、0 個錯誤、0 個音訊案例跳過。

| 干擾（每項 12 個條件） | SI-SDR 改善中位數 | 最低～最高 | 改善 ≥ 1 dB |
|---|---:|---:|---:|
| 錄製的風雨敲窗 | +6.70 dB | +3.16～+8.92 dB | 12/12 |
| 錄製的蒸汽列車 | +7.03 dB | +2.08～+10.10 dB | 12/12 |
| 錄製的吸塵器 | +7.64 dB | +3.38～+11.10 dB | 12/12 |
| 器樂曲《Vibe Ace》 | +1.20 dB | −0.88～+2.59 dB | 9/12 |
| 合成白噪聲 | +8.40 dB | +4.08～+10.65 dB | 12/12 |

**全部四個未達標案例**

| 條件 | 結果 | 預定門檻 |
|---|---:|---:|
| 朗讀者 5703 配音樂，輸入信噪比 +10 dB | +0.39 dB 改善 | ≥+1 dB |
| 雙人重疊配音樂，輸入信噪比 −5 dB | −0.88 dB，輸出劣於輸入 | ≥+1 dB |
| 雙人重疊配音樂，輸入信噪比 0 dB | +0.38 dB 改善 | ≥+1 dB |
| 只有音樂，抽取「人聲」 | 目標軌僅比輸入低 2.37 dB | ≥10 dB 衰減 |

其餘四個無人聲輸入，目標軌相對輸入的 RMS 各低 22.55 dB（風雨）、30.60 dB（列車）、19.52 dB（吸塵器）、11.71 dB（白噪聲）。靜音輸入輸出均為零。這項控制量測誤留在「人聲」軌的能量。產品沒有語音存在的二元判斷器，數字不應解讀成偵測正確率。

乾淨的三個朗讀和一個雙人重疊輸入均通過，輸出 SI-SDR 為 18.85～27.01 dB，人聲 RMS 降低 0.13～0.50 dB。四個案例音訊互相關峰值的延遲均為 0 樣本（搜尋範圍 ±20 ms）。全 70 個輸出的長度和聲道數符合輸入，目標加背景的最大全刻度波形誤差 2.98 × 10⁻⁸。

模型功能檢查 5/5 通過。RNNoise 可用，未設置和不存在的 Demucs 權重不會啟用對應功能，未知模型及不支援的 RNNoise 指定聲源會收到錯誤。此機沒有四軌 Demucs checkpoint，其實際推論列為 **SKIP**，與 70 個 RNNoise 案例分開計數。

**測試範圍。** 每位朗讀者取錄音開頭五秒。第四個語音條件將前兩位錯開 0.30 秒後重疊，目標是兩位說話者之和。每個條件以原始錄音、固定聲像及已知能量，在 −5、0、+10 dB 產生混音。五種干擾只有四段不同的真實素材和一種合成噪聲。重複同一段錄音改變信噪比不能當成獨立聽眾或新場景。以上數值量測聲波分離品質；它們不能支持辨別兩位人物、戶外實錄普遍品質、主觀自然度、三維定位或可懂度改善的結論。每種干擾僅有一段錄音，音樂負例顯示「只有音樂也會留下顯著人聲軌能量」的具體邊界。

**重現。** 需求為 Python、NumPy、FFmpeg（含 arnndn）與 Voice Hunter 原始碼。在 Voice Hunter 專案根目錄執行：

```bash
python3 qa_round1/rnnoise/evaluate.py --cache /tmp/voicehunter-rnnoise-eval --fetch
```

若使用獨立的 QA 檔案包，另指定 `--product-root /path/to/VoiceHunter`。快取已有音檔時可省略 `--fetch`。程式在重現前驗證每份素材的 SHA-256，選擇是否下載由使用者決定。七個來源的固定版本連結、原始 attribution 和授權資料列在 `sources.json`。三個朗讀錄音及樂曲的來源標示 CC BY 4.0。ESC-50 資料集標示 CC BY-NC 3.0，個別錄音 attribution 另列。此報告與測試包未附這些音檔。

`PROTOCOL.md` 是事前門檻，`cases.csv` 包含所有個別結果，`summary.json` 內含依音量和說話者彙整、環境和產品原始碼雜湊。本輪並未依測試結果修改產品或移除案例。
