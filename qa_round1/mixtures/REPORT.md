# 說話聲、列車、風聲同時混音

在三個受控場景中，透過產品公開的多軌 CLI 各匯出 speech、train、wind 以及 remaining，共九條目標聲軌。每個場景使用一位朗讀者、一段實錄列車和一段實錄風聲，共九份不同的原始素材。各聲源先有單獨示範段，再在後段同時出現，後段三個聲源的立體聲 RMS 相等。只把三個已命名的示範時間交給產品，以較後的獨立片段來評分。

**結果為 0/3 個場景三軌同時達標，5/9 條單軌達標。** 門檻預先定為每一條目標軌相對原始混音的 SI-SDR 改善至少 +3 dB。三個場景都成功寫出聲軌，最差加總重建誤差為 2.98 × 10⁻⁸ 全刻度，均通過預定的 10⁻⁶ 門檻。

| 場景 | 說話聲改善 | 列車改善 | 風聲改善 | 達標軌數 |
|---|---:|---:|---:|---:|
| LibriSpeech 198、ESC 第 1 折 | +5.76 dB | +0.88 dB | +1.05 dB | 1/3 |
| LibriSpeech 3436、ESC 第 2 折 | +4.40 dB | +2.29 dB | +3.62 dB | 2/3 |
| LibriSpeech 5703、ESC 第 3 折 | +5.18 dB | −0.27 dB | +4.19 dB | 2/3 |

三次人聲都通過，列車三次都低於門檻，風聲兩次通過。第三個場景的列車軌比直接使用受測混音略差。該測試顯示，即使音軌可精確合回、每個聲源都有單獨示範，這版算法處理不同真實素材的三種聲音重疊仍有實際限制。三個帶固定聲像的混音只涵蓋這批錄音，並未代表移動麥克風、車站反射或人們主觀聽感。

**重現。** `evaluate.py`、`PROTOCOL.md`、`sources.json` 和 `sources-scored.csv` 分別提供程式、事前條件、雜湊與授權，以及逐軌原始及處理後分數。測試錄音沒有包在交付檔。請保留旁邊的 `rnnoise/` 文件夾，以共用相同下載核對和 SI-SDR 計算。由 Voice Hunter 專案根目錄執行：

```bash
python3 qa_round1/mixtures/evaluate.py --cache /tmp/voicehunter-mixtures-eval --fetch
```

若單獨使用 QA 包，另指定 `--product-root /path/to/VoiceHunter`。快取有檔案時省略 `--fetch`。程式只在暫存目錄產生混音，跑完即清除；匯出的數值不含第三方音檔。原始素材的授權標示見 `sources.json`。本次無錯誤或跳過案例，產品程式沒有更改。
