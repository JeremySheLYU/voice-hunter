# 多軌 CLI 受控基準

所有九個場景皆成功輸出，九次的浮點聲軌加上剩餘軌都能重建輸入。以三條命名目標在全重疊段各自改善至少 3 dB 為通過條件。來源為合成諧波，測量採固定名稱，共用一個雙聲道比例的 SI-SDR，無最佳軌序重新配對。

| 三個目標的特徵 | 通過的種子 | 所有目標改善範圍 |
| --- | --- | --- |
| 頻段不同且穩定 | 3/3 | +19.4 至 +54.1 dB |
| 同方向、基頻接近 | 0/3 | −3.2 至 +2.7 dB |
| 進入重疊區後三者循環交換音區 | 0/3 | −94.4 至 −38.9 dB |

第三組刻意讓聲源的頻譜身分與示範衝突。極低 SI-SDR 源於估計波形與指定參考近乎正交；不代表真人聽到同等的音量損失。在種子 11 另做波形比對，第一軌和真實第三個聲源的相似度為 0.980，第二軌和第一個聲源為 0.998，第三軌和第二個聲源為 0.896。原有門檻與分軌名稱保持不動。

1 軌與 8 軌上下界均成功。測試主機上合成 60 秒、8 軌的單次 CLI 處理用時 4.28 秒，CLI 程序最高常駐記憶體約 643 MiB（非整機、非包含所有子程序的總和）；測得加總誤差 7.45 × 10⁻⁹。交換請求軌道順序後，對應聲軌最大差為 2.98 × 10⁻⁸。保留字作軌名時，CLI 拒絕並沒有留下輸出。計時期間有其他測試在同一台主機執行，時間只供本次參考。

專案根目錄執行 `OPENBLAS_NUM_THREADS=1 python3 qa_round1/multitrack/evaluate.py`。失敗品質案例完整寫入 results.json，跑完並寫出所有案例即正常結束，請讀 all_three_pass。事後診斷以 `python3 qa_round1/multitrack/identity_check.py` 重現。這組測試使用 macOS 或其他支援 wait4 的系統。
